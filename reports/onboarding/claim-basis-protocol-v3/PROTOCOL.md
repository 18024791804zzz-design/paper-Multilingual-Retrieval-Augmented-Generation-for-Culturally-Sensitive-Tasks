# 段落级W与“结论—依据”G标注规范 v3候选

本文件是操作规范提案与示例，不是全库重标结果。旧360条标签、原文、源码及requirements.txt均不改变。本轮不处理答案偏向性。

## 1. 核心范围

- 单位：原项目划分好的一个完整段落。语言、段落ID和目标领土只用于定位；不引入段外事实。
- 只读当前段落，不拼接相邻段、全文、其他检索结果、旧标签或Controller。不用模型记忆补出条约内容。
- W保留W1贬损/污名、W2褒扬/英雄化、W3确定性、W4情绪化隐喻、W5言说与可信度倾斜。
- G不按原G1-G5关键词逐类搜索。先抽取原段的关键命题，再反查段内依据及其支持范围。旧子类可作备注，但不作为必填标签。
- G仍是归因/依据关系的可见风险，不等于完整事实核验，不声称作者有意偏见。

## 2. 三种关系不能混为一谈

1. 事件原因：什么事件导致了结果？例如战争压力是否导致A国同意。
2. 依据关系：什么资料或事实支持这句话？协议条款可以支持“同意让渡”，却未必解释为什么同意。
3. 表达归属：是谁在断言？“B政府称A已同意”首先支持B作出了这一声明，不自动证明A实际同意。

因此，本协议使用“关键结论→段内依据→支持关系”检查；不要求每个事实都写出完整原因。

## 3. W判断

不能仅看到侵略、强占、非法、so-called、admitted、forzar、wring等词就判W。

完整阅读段落后检查：这是谁的话？是否直接/间接引语？有无否定、假设或历史限定？它是事实行为、术语、专名、作品标题，还是叙述者的额外评价？段内描述是否足以支持相应性质？

例如“缺少indisputable evidence”不是作者声称结论无可争议；明确引述某政府说主权无可争议，也不自动是作者W。强迫/侵略可能准确描述事件，不能为了中性把强迫改成双方自愿。中性替换可作辅助检查，但不能单独证明偏见。

## 4. G的逆向检查步骤

### 步骤A：抽取原段真正断言的关键结论C

优先检查领土让渡/承认、同意/拒绝、权利义务、违法/违约、政治动机/因果、权威/共识等高影响命题。普通人口、位置、面积、日期不必逐句追索条约或来源。

保留限定：是谁、对什么地区、作了什么、什么时候、是否发生/计划/承诺/否认、是否附条件。不要把原句“法院判给B”改写成“A同意割让给B”；那不是原句断言。

### 步骤B：识别表达者和叙述层级

区分作者断言、具名主体主张、法院/机构判断、间接引语、否定/假设。不要因为某国论证可疑，就把准确报道该论证的作者判G。

### 步骤C：反查当前段落中的依据E

E可以是协议中被报告的条款、联合声明、官方接受表示、法院判断、具体事件事实等，不只限于协议。每一项必须可引用当前段落原文。不得编造段外条款、用C的重复/同义改写充当独立E，也不能只凭出现一个协议名称就认为E充分。

“A签署并批准协议，条款明确同意X划给B”是明确的段内报道依据。它不需要逐字复制整份协议，但并未由此得到外部真实性验证。

### 步骤D：检查E与C是否对应

内部检查清单，不要求每段新增这些输出字段：

- 主体：A本人同意，还是仅B说A同意？
- 对象与范围：同一个X？一部分还是全部？
- 行为与权利：管理/驻军/通航/边界/主权不是同义词。
- 状态与时间：拟议/协商/承诺/批准/实施/完成是否被混淆？
- 条件：是否有尚未满足的生效或接受条件？
- 语气与归因：主张、否认、可能性是否被升级成确定事实？
- 权限与内容：裁判处理的是哪个问题？不能只因是权威机构就扩大到未处理的问题。

上述只判段内可见关系，不自行裁定国际法上的协议效力、默示同意或合法主权。

## 5. G判断边界

| 情况 | G判断 |
|---|---|
| 报道依据与结论对应，且归因/范围清楚 | 未发现G；不等于事实已核实 |
| 普通事实简述，未见需要特别归因的争议推论 | 不因没来源而判G/UNK |
| 只给协议名字，重大同意/让渡结论所需内容未显示 | UNK，不把“依据没展示”当作G证据 |
| 只有“A同意让渡X”等重大命题，来源及依据均未显示 | UNK，不证明事实为假或有偏见 |
| 段内明确只谈通航/临时管理，却据此断言永久主权让渡 | G：可定位的范围/性质扩大 |
| 未来协商被写为已经完成，或当事方主张被明显提升为作者已证实结论 | G：可定位的事件/归因升级 |
| 准确报道一方主张，并保留其主张主体或说明依据局限 | 不因所报道观点有方向或可疑就判作者G |

E不足以推出C，本身也不是所有情况下都能确认为G：若只是材料省略、内容尚不清楚，用UNK；确认G需要能指出具体的歪曲、范围扩大、归因漂移等段内证据。

尤其：法院判给B不等于A同意割让；撤军不自动等于放弃主权；沉默不自动等于明确同意；有协议不等于协议包含所述条款；有履约义务不等于已证明违约。若某法院/主体确实据此提出解释，应准确保留解释主体，不由标注器代其作最终裁决。

## 6. 简洁输出

核心字段仍是bias_label：NONE、UNK、W1-W5、G及已确认类型组合（如W3+G）。不输出答案方向。

仅对风险/疑难项另存findings：claim_quote、basis_quote（未显示可为null）、reason。均是原文引用或简短理由。无需给NONE段落生成长篇推理。

聚合：存在已确认W或G，保留这些类型；某个其他命题不确定不抹去已确认类型。没有已确认问题但存在需要核实的重大命题用UNK；没有可见W/G风险或重大疑难用NONE。NONE不等于真值认证、文章中立或所有来源可靠。

## 7. 能做与不能做

- 可以减少关键词误报、检查协议范围和引语主体、定位段内不当推论。
- 不能仅凭单段核实假协议、错误引文、伪造历史或段外事实，也不能证明全文不存在选择性呈现。
- 不能从这一套标注推断某措辞必然改变RAG输出，或直接得出应删整段。保留原文，处理策略另作实验。
- 适合一次LLM调用完成命题抽取与关系判断；程序仅校验标签、引用存在及格式，不验证语义正确。
- real_examples.json中的4例是当前助手按规则作的说明性阅读；constructed_examples.json为9个构造案例。不是独立金标准或分类器性能评测。
